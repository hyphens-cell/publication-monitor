# Система мониторинга публикационной активности кафедр университета

Внутренняя информационная система университета для планирования, учета, контроля и анализа публикационной активности кафедр.

## 1. Назначение

Система предназначена для:

- учета публикационной активности кафедр;
- формирования годовых планов публикаций;
- согласования годовых планов;
- контроля выполнения утвержденных планов;
- ведения карточек публикаций;
- проверки корректности публикационных данных;
- контроля попыток добавления дублирующихся публикаций;
- проверки аффилиации;
- хранения подтверждающих материалов;
- мониторинга публикационной активности;
- аналитики и отчетности;
- поддержки управленческих решений Департамента науки и инноваций.

Система используется исключительно внутри университета. Доступ предоставляется только авторизованным пользователям согласно ролям и правам доступа.

На первом этапе система работает автономно. Интеграции со Scopus, Web of Science, Crossref и другими внешними научными сервисами не реализуются. Данные вводятся пользователями вручную.

Архитектура должна оставлять возможность для будущих интеграций.

## 5. Роли

### Технический администратор

- создание, редактирование, блокировка и удаление учетных записей;
- создание, редактирование и архивирование кафедр;
- архивирование и восстановление архивных данных;
- полный доступ к журналу событий;
- поиск, фильтрация и экспорт журнала;
- управление резервным копированием;
- восстановление данных;
- просмотр состояния системы.

Технический администратор не участвует в проверке публикационной деятельности и не принимает управленческие решения по публикациям.

### Монитор / Администратор

- просмотр планов всех кафедр;
- одобрение планов;
- возврат планов на доработку с комментариями;
- просмотр публикаций всех кафедр;
- проверка публикаций;
- ручная проверка аффилиации;
- комментарии к планам и публикациям;
- мониторинг выполнения;
- аналитика и статистика;
- контроль попыток добавления дубликатов;
- просмотр истории изменений;
- управление предметными справочниками.

Администратор не управляет учетными записями пользователей, не изменяет структуру системы, не редактирует и не очищает журнал событий и не удаляет пользовательские публикации.

### Заведующий кафедрой

- авторизация;
- создание годового плана;
- отправка плана на согласование;
- просмотр статуса согласования;
- ведение публикаций;
- изменение статусов публикаций;
- заполнение итоговой информации;
- загрузка подтверждающих файлов;
- просмотр и обработка замечаний;
- внесение изменений после возврата на доработку;
- просмотр статистики выполнения плана.

У одной кафедры может быть только один ответственный пользователь.

## 6. Годовой план

Годовой план формируется на следующий календарный год.

План представляет собой перечень планируемых публикаций.

Для планируемой публикации указываются:

- название статьи;
- тип публикации;
- предполагаемое издание или журнал;
- предполагаемый квартиль;
- предполагаемые авторы;
- планируемая дата публикации.

До отправки на согласование заведующий кафедрой может редактировать план.

Для одного календарного года допускается только один план публикационной активности.

### Согласование

```text
Черновик
   |
   v
На согласовании
   |
   +------> Утвержден
   |
   +------> На доработке
                  |
                  v
             Исправление
                  |
                  v
          Повторное согласование
```

При возврате администратор обязан указать замечания.

После утверждения редактирование плана пользователем блокируется.

При необходимости изменения утвержденного плана создается запрос на корректировку. Версии плана, комментарии и решения сохраняются.

## 7. Публикации

После утверждения годового плана каждая запланированная публикация становится рабочей записью публикации.

Для публикации хранятся:

- окончательное название;
- DOI;
- ссылка;
- авторы;
- журнал или издание;
- год публикации;
- том;
- номер выпуска;
- страницы;
- сведения об индексации;
- квартиль;
- аффилиация;
- примечания.

### Статусы

- Подготовка статьи;
- Отправлена в журнал;
- На рецензировании;
- Требуется доработка;
- Принята к публикации;
- Опубликована;
- Отклонена.

При изменении статуса сохраняются дата, пользователь и предыдущий статус.

## 8. Подтверждающие материалы

После публикации пользователь загружает подтверждающий файл, например первую страницу опубликованной статьи.

Поддерживаемые форматы:

- PDF;
- DOC;
- DOCX;
- JPG;
- JPEG;
- ZIP;
- RAR.

Файлы хранятся в файловом хранилище, а метаданные файла — в PostgreSQL.

## 9. Проверка публикации

Администратор проверяет:

- соответствие утвержденному плану;
- корректность заполнения;
- аффилиацию;
- наличие подтверждающего файла;
- отсутствие дубликата.

При необходимости администратор оставляет комментарий.

Комментарии отображаются в системе и направляются на корпоративную электронную почту.

## 10. Дубликаты

На первом этапе проверка выполняется внутри системы по имеющимся данным.

Приоритет проверки:

```text
DOI
  |
  v
Название
  |
  v
Дополнительные библиографические признаки
```

Система должна выявлять возможные дублирующиеся публикации и передавать решение администратору.

## 11. Аффилиация

Если основным местом работы автора является университет, университет должен указываться первым в списке аффилиаций.

На первом этапе проверка аффилиации выполняется администратором вручную.

## 12. Уведомления

Уведомления работают двумя каналами:

```text
Событие
  |
  +----> 🔔 Внутри системы
  |
  +----> 📧 Корпоративная почта
```

Основные события:

- план отправлен на согласование;
- план утвержден;
- план возвращен на доработку;
- добавлено замечание;
- публикация требует доработки;
- обнаружен возможный дубликат;
- публикация проверена;
- возникает угроза невыполнения плана.

Цветовая индикация:

- зеленый — работа / план принят;
- желтый — требует внимания / доработки;
- красный — угроза невыполнения.

## 13. Мониторинг и прогресс

Система автоматически рассчитывает выполнение годового плана.

Основной показатель:

```text
Количество опубликованных публикаций
------------------------------------ × 100%
Количество публикаций, утвержденных в плане
```

На основании процента формируется предварительная оценка выполнения.

Администратор может изменить автоматическую оценку вручную с обязательным комментарием-пояснением.

Мониторинг используется для:

- сравнения плана и факта;
- контроля выполнения кафедр;
- выявления отстающих кафедр;
- анализа распределения публикационной нагрузки.

## 14. Аналитика

На первом этапе используются стандартные визуализации:

- динамика публикаций по времени;
- сравнение кафедр;
- распределение публикаций по типам;
- план / факт / процент выполнения;
- рейтинговые таблицы кафедр.

Аналитические материалы строятся на данных системы.

## 15. Отчеты

Основная форма отчета:

```text
Наименование | План | Факт | Процент выполнения | Примечание
```

Предусматриваются фильтры по:

- году;
- кафедре;
- типу публикации;
- сотруднику;
- статусу.

Для формирования отчетов и экспорта используются Excel/PDF-инструменты проекта.

## 17. Журналирование

Для важных действий фиксируются:

```text
пользователь
дата и время
действие
объект
результат / дополнительные сведения
```

Журнал используется для контроля действий и просмотра истории изменений.

История публикаций и история версий планов сохраняются отдельно от общего журнала событий.

## 18. Резервное копирование

Резервное копирование выполняется для PostgreSQL.

```text
PostgreSQL
    |
    v
pg_dump
    |
    v
backups/
```

Предусматриваются:

- автоматическое резервное копирование;
- ручное создание резервной копии;
- хранение резервных копий;
- восстановление из резервной копии.

Управление резервным копированием и восстановлением относится к функциям технического администратора.
