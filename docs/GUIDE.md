# Publication Monitor 2.0 — пользовательский гид

Этот гид описывает ежедневную работу в системе. Названия пунктов приведены на русском; при выборе `ҚАЗ` интерфейс и статусы переключаются на казахский без потери текущей страницы и фильтров.

## Вход и язык

1. Откройте адрес системы, выданный администратором.
2. Введите логин и пароль.
3. Для смены языка нажмите `RU` или `ҚАЗ` в верхней панели.
4. После работы откройте меню профиля и нажмите **Выйти**.

Если учётная запись заблокирована или деактивирована, вход невозможен. Не передавайте пароль другим пользователям.

## Заведующий кафедрой

### Сотрудники

Раздел **Сотрудники** содержит только сотрудников вашей кафедры. Здесь можно добавлять, редактировать, архивировать и восстанавливать записи. Архивирование сохраняет историю связей с планами и публикациями.

### Годовой план

1. Откройте **Планы** и создайте план на нужный год.
2. Добавьте пункты: название, тип публикации, журнал, квартиль и авторов.
3. Проверьте состав плана и нажмите **Отправить на согласование**.
4. После возврата прочитайте комментарий, внесите изменения и отправьте план повторно.
5. Утверждённый план недоступен для произвольного редактирования; изменения проходят через предусмотренный workflow.

Статусы плана: **Черновик → На согласовании → Утверждён** или **Возвращён на доработку**.

### Публикации и вложения

Публикации из утверждённого плана появляются автоматически. Откройте публикацию, заполните фактические данные и обновляйте статус только разрешёнными переходами.

Для подтверждения результата:

1. откройте карточку публикации;
2. выберите файл в блоке вложений;
3. загрузите его;
4. дождитесь решения монитора.

Пользователь может скачивать только доступные ему файлы, а удалять — только разрешённые собственной ролью и принадлежностью записи.

## Монитор (`ADMIN`)

### Согласование планов

В разделе **Планы** выберите отправленный план. Монитор может:

- утвердить корректный план;
- вернуть его на доработку с обязательным комментарием;
- посмотреть версии и историю согласования;
- запросить или отклонить корректировку в предусмотренных V2-сценариях.

Повторное утверждение не создаёт дубликаты публикаций.

### Проверка публикаций

Перед подтверждением проверьте связь с утверждённым планом, кафедру, название, журнал, квартиль, авторов, аффилиацию, DOI и одобренные вложения.

Результаты проверки:

- **На проверке** — решение ещё не принято;
- **Проверена** — данные подтверждены;
- **Возвращена на доработку** — требуется комментарий;
- **Дубликат** — конфликт разрешён выбором оригинальной записи.

### Мониторинг, аналитика и отчёты

- **Мониторинг** показывает выполнение планов по кафедрам и годам.
- **Аналитика** сравнивает плановые и фактические значения.
- **Отчёты** формируют фильтрованные Excel/PDF-файлы.

Фильтры года, кафедры и статусов применяются на сервере. Для заведующего выборка дополнительно ограничивается собственной кафедрой.

## Технический администратор

### Пользователи и кафедры

Технический администратор создаёт учётные записи, назначает роль и кафедру, блокирует и разблокирует пользователей. Система защищает текущего TECH_ADMIN от случайной самоблокировки, самоудаления и понижения роли.

Кафедры можно создавать, редактировать, архивировать и восстанавливать. Нельзя архивировать кафедру, если это создаёт некорректное состояние связанных данных.

### Справочники и аудит

**Справочники** содержат двуязычные значения классификаторов. Для каждого значения указываются код, русское и казахское название, порядок и активность.

**Журнал действий** фиксирует пользователя, действие, объект, время, IP и детали. Доступны фильтры и CSV-экспорт. Технические коды событий в интерфейсе заменены понятными RU/KK-названиями.

### Состояние системы и backup

Страница **Состояние системы** показывает доступность БД, количество основных сущностей, объём uploads и использование диска.

Страница **Резервные копии** позволяет:

- создать PostgreSQL custom dump;
- увидеть дату и размер файла;
- скачать существующую копию.

Пароль БД читается из `DATABASE_URL` или `DB_PASSWORD`. Если `pg_dump` отсутствует либо завершился ошибкой, пользователь получает понятное сообщение, а неполный файл удаляется.

## Статусы публикации

| Этап | Смысл |
|---|---|
| Подготовка статьи | Работа ещё готовится |
| Отправлена в журнал | Рукопись передана журналу |
| На рецензировании | Идёт внешняя проверка |
| Требуется доработка | Журнал запросил изменения |
| Принята к публикации | Получено подтверждение |
| Опубликована | Работа вышла |
| Отклонена | Публикация не принята |

## Частые вопросы

**Почему я не вижу чужую кафедру?**
Для заведующего это штатное ограничение безопасности. Доступ проверяется не только меню, но и сервером.

**Почему план нельзя изменить?**
Утверждённый план защищён от прямого редактирования. Используйте предусмотренный запрос корректировки.

**Почему файл не загружается?**
Проверьте допустимый формат и максимальный размер, заданный `MAX_UPLOAD_BYTES`.

**Почему backup не создаётся?**
Backup работает только с PostgreSQL и требует доступный в `PATH` `pg_dump`, совместимый с версией сервера.

**Почему после смены языка сохранились фильтры?**
Это ожидаемое поведение V2: язык меняется без потери текущего URL и query string.

## Поддержка

При обращении к техническому администратору укажите страницу, время ошибки и выполняемое действие. Не отправляйте пароль, `SECRET_KEY`, `DATABASE_URL` или содержимое `.env`.
